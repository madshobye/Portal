Capability

Local-first projects

A XOBIT project is more than a code file. It keeps revisions, script code, AI chat, specification, circuit notes, and UI/circuit context together in the browser where you are making the work.

How It Works

  1. A project is the container. It has a name, stable id, revision list, and the currently selected revision.
  2. A revision captures a state of thought. Code, specification, chat history, circuit JSON, source, time, and byte size belong to the revision.
  3. Local storage keeps work close. Projects live in browser local storage unless you explicitly export them.
  4. Export is the backup path. Download a project JSON when the work matters, when changing browsers, or before clearing data.

Why It Matters

Physical computing work often changes direction. Keeping code, AI reasoning, documentation, and circuit assumptions together makes it easier to return to a previous idea without reconstructing why it existed.

No cloud backup by default

The design is intentionally local-first. The board stores the running sketch, and the browser stores projects and revisions. Export regularly when the work should survive browser resets or machine changes.
