Capability

Live board coding

XOBIT treats the ESP32 as a live programmable object: edit a script in the browser, upload it to the board, watch logs, stop it, and recover the running code when you need to inspect what is actually on the device.

How It Works

  1. The browser editor owns the draft. The Code view stores your current project and revision locally in the browser.
  2. Upload compiles the script on the board. The firmware receives source text, stops any old script, compiles the new code, and starts it if compilation succeeds.
  3. The script runs in a firmware-managed task. `setup()` runs once, then `loop()` is called repeatedly while USB or online transport remains responsive.
  4. Logs and errors come back to the console. `print()`, `println()`, API errors, compile errors, and runtime status are returned to the browser.
  5. Recover reads from the device. When you need the truth, recover asks the board for the stored/running sketch rather than trusting the browser draft.

Good Habits

  • Keep `loop()` short; do one frame of work, then return or use a small `delay()`.
  • Upload small changes first when debugging physical behavior.
  • Read the console after every upload; compile and runtime errors usually point to the failing boundary.
  • Use `lastError()` and `clearError()` when a sketch needs to expose errors in its own UI.
