Open Editor

ESP32 creative coding environment

P1.E lets a board become a live, scriptable object.

Write small Wrench sketches in the browser, run them on an ESP32, control LEDs and pins, build a live UI, connect over USB or MQTT, and let the AI assistant help shape code and documentation around the project you are making.

  • Code, upload, stop, inspect logs, and recover sketches from the board.
  • Keep projects as revisions with code, chat, specification, and circuit notes together.
  • Drive NeoPixel-style LED strips, GPIO, HTTP APIs, time, sun position, UI controls, and Home Assistant entities.
Early maturing system

P1.E is already quite stable, but the firmware is under rapid development. Expect to find bugs sometimes, and expect to update the board firmware as the system matures.

The core system is designed to be independent of cloud subscriptions: the main parts are a static HTML page and firmware on the board. Two optional parts use cloud services: internet connection needs an MQTT broker, and chat needs a ChatGPT API key. A public MQTT broker can work for initial testing because P1.E encrypts its own communication. Other LLM providers may be added later.

There are no cloud backups of your sketches. The running code lives on the board, while projects, revisions, chat, and specifications are stored in your browser local storage. Export projects and make regular backups when the work matters.

P1.E is built around a few connected views: AI for shaping the sketch and specification, Code for editing and uploading, Circuit for wiring notes, and UI for the live controls declared by the running sketch.

Getting Started

The first setup flow gives the board enough information to join your network, identify itself, and use the AI features in the browser. USB is the simplest way to start; MQTT is useful once the board is on WiFi.

  1. Install firmware. Open the Install tab, connect the ESP32 over USB, and flash the current P1.E firmware.
  2. Add WiFi. Open Settings, add the network name and password, save, and reboot if the board asks for it.
  3. Name the board. Use Settings > General to set a friendly device name. This name is shown in the status bar and integrations.
  4. Add online users. In Settings > Users, create a user name and password for MQTT sign-in. Guest UI access can be enabled separately.
  5. Add a ChatGPT key. In Settings > AI, save an API key in the browser. The key stays local to the browser unless you create an obfuscated sharing key.

Writing Wrench Sketches

A P1.E sketch usually has a setup() function for one-time configuration and a loop() function that does a small slice of work repeatedly. Keep loops short so the board can keep communicating while your code runs.

// Prints a heartbeat once per second.
var lastPrintAt = 0;

function setup() {
  println("ready");
}

function loop() {
  if ((millis() - lastPrintAt) >= 1000) {
    lastPrintAt = millis();
    println("alive");
  }
  delay(10);
}
  • Declare new variables with var, for example var count = 0;.
  • Use while loops and remember to increment your counter.
  • For LED animation, predeclare scratch arrays and reuse them inside hot loops.
  • Avoid long blocking loops in setup() or loop().

Bindings

Bindings are the functions a Wrench sketch can call to reach firmware features. The examples below show the preferred current style: explicit setup, short runtime loops, and reusable buffers when data is updated often.

LED Strips

NeoPixel-style output
Open detailed reference
  • ledConfig(strip, pin, count, brightness) configures a WS2812B/NeoPixel-style strip with GRB order.
  • ledConfig(strip, pin, count, brightness, "WS2812B", order) supports explicit color orders such as RGB, GRB, and BGR.
  • ledSet(), ledSetHsv(), ledFill(), ledClear(), ledShow(), ledBrightness()
  • ledGetRgb(strip, index, out), rgbToHsv(rgb, out), hsvToRgb(hsv, out)
var pos = 0;

function setup() {
  ledConfig(0, 4, 30, 70);
  ledClear(0, 1);
}

function loop() {
  ledClear(0, 0);
  ledSetHsv(0, pos, (pos * 8) % 255, 255, 180);
  ledShow();
  pos = (pos + 1) % ledCount(0);
  delay(50);
}

function setup() {
  ledConfig(0, 4, 30, 80);
  paletteSet2(0, 20, 0, 120, 255, 110, 0);
}

function loop() {
  var i = 0;
  while (i < ledCount(0)) {
    paletteGetRgb(0, (i * 255) / ledCount(0), rgb);
    ledSetRgb(0, i, rgb);
    i = i + 1;
  }
  ledShow();
  delay(40);
}

Useful Patterns

These habits keep sketches responsive and reduce memory pressure while still allowing rich behavior.

  • Prefer reusable output buffers. Use timeLocal(out), sunLocal(..., out), ledGetRgb(..., out), and rgbToHsv(rgb, out) in repeated loops.
  • Keep LED frames bounded. Draw one frame, call ledShow(), then leave a small delay().
  • Use firmware JSON cache for APIs. fetchJson() plus getJsonValue() avoids copying a large response into Wrench when you only need a few fields.
  • Rebuild UI only on hello. Call uiBegin() in setup() and after uiEventIs("hello"); use uiUpdate() for live values.
var rgb[] = { 0, 0, 0 };
var hsv[] = { 0, 0, 0 };

function loop() {
  var i = 0;
  while (i < ledCount(0)) {
    ledGetRgb(0, i, rgb);
    rgbToHsv(rgb, hsv);
    hsv[0] = (hsv[0] + 8) % 255;
    hsvToRgb(hsv, rgb);
    ledSetRgb(0, i, rgb);
    i = i + 1;
  }
  ledShow();
  delay(30);
}
