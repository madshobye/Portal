01 / THE BASIC IDEA

Draw your interface each frame.

uiSlim is an immediate-mode UI for the p5 canvas: call a widget in draw(), then use its result. Styles are JavaScript objects, not CSS. Portal loads uiSlim2.js and updates its pointer input for you.

Start from the Portal cloud base sketch or local base sketch. Keep its HTML and Portal loader; replace sketch.js with one of the complete examples below.

function setup() {
  createCanvas(windowWidth, windowHeight);
}

function draw() {
  background(245);
  uiListStart({ x: 20, y: 20, width: 260 });
  if (uiButton("Run").clicked) {
    console.log("Run once on release");
  }
  const speed = uiSlider("speed", "Speed", {
    min: 0, max: 10, init: 3
  }).value;
  uiText(`Speed: ${speed.toFixed(1)}`);
  uiListEnd();
}

The embedded previews load p5 and the repository’s uiSlim module directly, so they update input themselves. In a normal Portal sketch, do not add a second uiUpdateSimple() call.

Interactive widgets also return their bounding box. A prompt is a browser dialog, not an editable field drawn on the canvas. For keyboard-accessible forms or rich text entry, use HTML controls alongside the sketch.

03 / LOCAL OVERRIDES

Style one control

Most widgets merge common → component → local style. A button then applies hover or pressed; pressed takes priority. The merge is deep: changing one nested property keeps its siblings.

uiButton("Launch", {
  height: 48,
  fontSize: 18,
  bgColor: "#c62630",
  textColor: "#ffffff",
  rounding: 24,
  hover: { bgColor: "#a91d28" },
  pressed: { bgColor: "#74141c" }
});

disabled: true suppresses interaction on buttons and prompt buttons. Supply your own disabled colors; there is no automatic disabled theme. Sliders and toggles do not implement that option.

Toggle styles additionally inherit button styles. Their on/off colors replace the normal background, and hover/pressed styling applies only while off. Sliders render trackColor and fillColor, not the common background or button state styles.

04 / A SHARED STYLESHEET

One panel, three themes

Call uiSetBaseStyle() in setup() to style the whole sketch. Use common for shared properties and component keys for exceptions: button, text, slider, toggle, promptText, and list.

uiSetBaseStyle({
  common: { height: 40, fontSize: 16, rounding: 10 },
  button: { hAlign: "center" },
  text: { bgColor: false },
  slider: { trackColor: "#ece6dc", fillColor: "#efaf91" },
  toggle: { onBgColor: "#bce2ca", offBgColor: "#ece6dc" },
  list: { width: 280, dir: "vertical" }
});

Base style updates merge into the current theme; they do not reset it. When switching themes at runtime, explicitly replace every property you want to change. Plot-specific defaults live inside uiPlot(); pass its colors directly as in the plot example.

05 / GIVE CONTROLS ROOM

Lists and absolute placement

  • Vertical: the list controls widget width; each widget controls its height.
  • Horizontal: give each widget a width. The list does not wrap automatically.
  • Spacing: set margin on uiListStart(). Widget margins do not individually move the list cursor. The default list spacing comes from common.margin.
  • Absolute: supply x, y, and width together. The control no longer advances the list.
  • Nested lists: positions are relative to the parent, but ending a child does not advance the parent cursor. Reserve space explicitly or use separate lists as above.

Balance every uiListStart() with uiListEnd() on every frame. For responsive panels, compute widths from the current canvas width. uiSlim does not apply CSS breakpoints or automatic text wrapping.

06 / CONTINUOUS INPUT

Sliders as faders and meters

The third argument supplies min, max, init, and optional syncValue. Keep visual properties in the fourth argument for clarity. Style properties in the third argument also work, but the fourth argument wins.

const result = uiSlider("brightness", "Brightness", {
  min: 0, max: 255, init: 128
}, {
  trackColor: "#222222", fillColor: "#ffbb66",
  textColor: "#ffffff", hideValue: true
});
const brightness = Math.round(result.value);

There is no step option. hideValue hides the numerical suffix; hideText hides the whole label. syncValue follows an external number while the slider is not being dragged. Its synchronization does not set changed; that flag reports a drag changing the value.

07 / SHOW YOUR DATA

Plot live data

Each series can be an array of numbers, or an object such as { label, values, color, weight }. Values may also be [x, y] pairs or { x, y } objects. Add type: "points", pointSize: 4 to a series for a scatter plot.

Set xMin, xMax, yMin, and yMax for stable axes, or omit them for automatic ranges. Use showGrid, showLabels, showRangeLabels, headerItems, and footerText to simplify the display. hoverValue contains the pointer’s x-value and y-range, not the nearest sample.

08 / KEEP THIS HANDY

Style reference

Sizes and coordinates are canvas pixels. These are supported fields, not CSS property names. Some properties apply only to particular widgets.

PropertiesMeaning / example

09 / EVERYDAY RECIPES

State that stays useful

Stateful widgets use an ID separate from their label. Keep IDs unique and stable: "synth-volume" identifies the value while "Volume" is what people see. By default, slider, toggle and prompt values are saved in local storage under uiSlim2:<id>. Sketches on the same origin can share these keys.

init is only the initial fallback. A saved value can override it. These live examples pass persist: false directly to each widget to start fresh on reload.

// Read or update in-memory state.
const speed = uiGet("speed", 3);
uiSet("speed", 5);

// Update state and its saved value (e.g. a reset button).
if (uiButton("Reset speed").clicked) {
  uiSetState("speed", 3);
}

// A temporary toggle: pass persistence on the widget itself.
const preview = uiToggle("preview", "Preview", {
  persist: false, showStateText: true
}).value;

Use a custom font

async function setup() {
  createCanvas(windowWidth, windowHeight);
  const font = await loadFont("assets/MyFont.ttf");
  uiSetBaseStyle({ common: { font, fontSize: 16 } });
}

Draw into a graphics buffer

Create a p5.Graphics buffer once in setup. Use uiUseGraphics(panel) before drawing controls and uiEndUseGraphics() afterwards. Display it at (0, 0) at its original size so the canvas pointer coordinates match. Moving or scaling the buffer requires matching input-coordinate conversion; changing the drawing target alone does not do that.

// setup(): panel = createGraphics(width, height);
// draw():
panel.clear();
uiUseGraphics(panel);
uiButton("On the buffer", { x: 20, y: 20, width: 220 });
uiEndUseGraphics();
image(panel, 0, 0);

Keep debug information separate

uiDebug("message") sends information to Portal’s debug console. uiDrawOnDebugOverlay(() => { /* drawing */ }) queues custom overlay drawing. Use normal widgets in draw() for controls that should always be visible.
